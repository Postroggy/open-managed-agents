第一章 · 三层结构

从组织到用户

🏢
Organization（组织）
最高层：一个公司/团队
organizations.uuid
▼ 拥有
📁
Workspace（工作区）
中间层：组织下的一个部门/项目空间
workspaces.uuid + organization_uuid
▼ 包含
👤
User（用户）
底层：具体的人，通过 workspace_members 加入工作区
users.uuid + workspace_members(uuid × 3)

💡 注意：User 属于 Organization（users.organization_uuid），
而 User 进入 Workspace 靠 workspace_members 关联表（多对多）。

第三章 · 鉴权边界

代码里怎么保证隔离？

🔑 Principal（请求身份） 携带三个关键 UUID：
OrganizationUUID · WorkspaceUUID · APIKeyUUID

✅ 所有资源查询都带 workspace_uuid 过滤（多租户边界）：
WHERE workspace_uuid = #{workspaceUUID}

🚫 跨工作区访问 → 查不到（返回 not found），不是权限错误

第四章 · 回到 memory

记忆在哪一层？

🧠 Memory Store 挂在 Workspace 下：
memory_stores.workspace_uuid

📂 Memory 对象 key 也带 workspace：
workspaces/{workspaceUUID}/memory_versions/...

→ 记忆是 工作区级别 的资源：同工作区的 Agent 共享记忆，跨工作区隔离。
