🧰 internal/common
公共小工具箱

🪛 像「家庭工具箱」一样
谁都能拿来用的小工具
第一章 · 它是什么

为什么要有「公共」工具？

很多包都需要 处理字符串、转换 JSON。
与其每个包自己写一遍，不如放在一个 大家都认识 的地方。

internal/common 不是一个大包，而是 两个小工具包：

🗂️ collections —— 集合操作（字符串处理）
🧩 jsonx —— JSON 转换工具

⚠️ 注意：它自己不依赖任何业务包（领域无关），只被别人用。

第二章 · 两个小工具箱

里面有什么？

🗂️
collections
internal/common/collections/strings.go
处理字符串集合的小帮手

IsBlank —— 是不是空白？
UniqueTrimmedStrings —— 去空白、去重复
StringSet —— 变成员集合（查得快）
🧩
jsonx
internal/common/jsonx/jsonx.go
在 Go 值和 JSON 之间转换

Encode —— 值 → JSON
Decode —— JSON → 值
IsNull —— 是不是 null？
Default —— 空的给默认值
第三章 · 设计原则

什么时候该放 common？

✅ 放 common：领域无关、多个包都用、行为稳定
❌ 不放 common：跟特定业务强相关（如 agent 逻辑）、只在某个包用

common 里没有业务概念 —— 你看不到 "agent"、"session"、"batch" 这些词， 只有最通用的字符串和 JSON 操作。

第四章 · 谁在用

工具箱借给了谁？

environments networkpolicy deployments httpapi e2bruntime

这些包各自实现自己的业务，但字符串和 JSON 的小事，都找 common 借。
