🍎 apperr 是什么？

业务代码里的「错误」，和 HTTP 格式的「错误」，是两件事

🍎
apperr = 应用错误包：与 HTTP 无关的业务错误
业务层只管说「什么东西错了」，不管「该返回什么状态码」
外层（httpapi）再把错误翻译成 Anthropic 兼容的格式 🗣️
🍎

🧬 apperr.Error 长什么样？（真实代码）
// 三个字段：种类 + 对外话术 + 内部原因
type Error struct {
  Kind Kind // 错误种类（14 种之一）
  PublicMessage string // 能告诉用户的话
  cause error // 内部原因（对外保密）
}
🔒 关键：PublicMessage 是唯一能对外暴露的；Error() 只会返回内部 cause —— 绝不泄漏内部细节

💡 看完代码的 Insight
🪶 传输无关

apperr 不含 HTTP 状态码或 wire error type —— 同一错误可用于 HTTP、队列、worker 等任何出口。

🔒 防泄漏

PublicMessage 与 cause 分离：对外只说安全的话，内部细节走 Error() 只在日志里出现。

🧩 统一边界

所有资源包集中在各自的 errors.go 定义错误合同，httpapi 只负责最后一跳翻译 —— 各管各的。

🛡️ 兜底机制

不是 apperr（未知错误）→ 统一 500 + "Internal server error"，绝不把内部错误细节暴露给用户。
