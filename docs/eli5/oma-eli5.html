Open Managed Agents
是什么？

一句话：把别人家的米其林菜单，
搬进你自己家的厨房。

第 1 章 · 这是什么？

Anthropic 有一家"云餐厅"→ OMA 是你家的厨房

🏙️
Anthropic 云餐厅
（Managed Agents 云服务）
厨房在别人的大楼里
要联网、要付钱、要排队
vs
🏠
OMA 本地厨房
（你电脑上跑的服务）
免费、离线、随开随用
菜谱完全开源

Anthropic 的云服务有一套菜单（API）：点一个 agent、开一个 session、传一个文件……

OMA 把这份菜单原封不动地抄了一份，然后在你自己电脑上开灶。

关键是：点菜机器人（SDK）不用改！——用 Anthropic 官方 Go / Python / TypeScript SDK 写好的程序，只要把地址改成 localhost，立刻就能在家里跑起来。

"菜单一模一样" = API 兼容 = 这是整个项目最重要的一件事。

第 2 章 · 为什么要有它？

三个理由→

01

本地开发

不联网、不花钱、不用等云端。改代码 → 重启 → 马上试。

02

SDK 验证

官方 SDK 直接对着它跑测试，确认你的程序与 Anthropic API 完全兼容。

03

产品化

它不止是个测试台——自带的网页控制台和全套资源管理，可以一路升级成真产品。

web/ · React
➜
🚪 OMA 服务器
Go · 入口 + 鉴权
internal/api + main.go
➜
👨‍🍳 资源小厨房
一个资源一个包
agents / sessions / files …
➜
📦 三个仓库
PostgreSQL / Redis / MinIO
📒
PostgreSQL 记账本
所有"记录"：谁建的 agent、session 状态…
🧻
Redis 便利贴
临时登录会话，丢了也无所谓
🏬
MinIO / S3 大仓库
大件物品：文件、skill 包、批量结果

记账本只记"东西放哪了"，不放东西本身。文件内容存进 MinIO 仓库，PostgreSQL 里只写一行："这个文件叫啥、放在哪个仓库角落、谁传的"。

第 4 章 · 餐厅有两份菜单

一份给"点菜机器人"，一份给"自家平板"→

🥡 /v1/* 菜单
给点菜机器人（SDK）用 —— 和 Anthropic 官方一模一样的菜单
门票：Bearer sk-ant-xxx（API key）
  • /v1/agents
  • /v1/sessions
  • /v1/files
  • /v1/skills
  • /v1/deployments
  • /v1/vaults / webhooks …
🖥️ /api、/auth、/web-api 菜单
给自家平板（网页控制台）用 —— 组织管理、登录、工作区
门票：cookie session（登录后发放）
  • /api/organizations/…
  • /api/console/organizations/…
  • /auth/…（登录）
  • /oauth/…
门口的保安看门票分路：拿着 API key 的 → 走 /v1 服务通道；
拿着 session cookie 的 → 走平台通道。看 server.go 的 apiEntrypointRouter 就是这个保安。
第 5 章 · 想学代码？先看地图

仓库结构 —— 每个文件夹是干什么的→

├── main.go # 大门：加载配置、连数据库、启动服务器
├── internal/api # 前台大堂：组装 + 路由 + 鉴权入口（先读这个！）
├── internal/agents # 👨‍🍳 小厨房1：agent 资源
├── internal/sessions # 👨‍🍳 小厨房2：session 资源
├── internal/files # 👨‍🍳 小厨房3：文件资源（最好上手的一个）
├── internal/…skills、memory、vaults、batches… # 每个资源一个包
├── internal/db # 📒 记账本管理员：只存取数据，不懂 HTTP
├── internal/httpapi # 统一"话术"：Anthropic 兼容的错误格式
├── internal/storage # 🏬 仓库管理员：S3/MinIO 存取
├── web/ # 🖥️ 自家平板：React 控制台
└── tests/ # 验收员：SDK 兼容测试
🏷️ 铁律（依赖方向）：api → 资源包 → db，只准往下，不准往上。
   记账本管理员永远不需要知道大堂长什么样。
第 6 章 · 听个小故事

"上传一个文件"是怎么完成的→

第 1 步 · 点菜

SDK 发出 POST /v1/files，口袋里揣着门票 Bearer sk-ant-local-default（默认开发 key）。

第 2 步 · 保安查票

入口把门票哈希后去数据库核对 → 通过。查到是谁之后，把"他是哪个组织的"写进请求里随身带着。

第 3 步 · 送到小厨房

路由把请求交给 internal/files 的 handler。

第 4 步 · 存东西

文件内容 → 存进 MinIO 大仓库；"文件名、放哪了、谁传的" → 记进 PostgreSQL 记账本。

第 5 步 · 回话

用 Anthropic 兼容的格式回答："好了，这是你的文件 ID：file_xxx"。SDK 完全听不懂区别。
