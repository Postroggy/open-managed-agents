🪞 快照是「镜像」，不是「人」

快照只是 agent 数据的静态拷贝（JSON），不是 agent 本人。它把数据库里那个会变的对象，凝固成一份能到处传递、不依赖数据库的「文件」。

🔌 它没有自己的入口

agentsnapshot 没有 handler、没有路由 —— 它是纯工具包，只被别人调用（agents 创建时拍、skillprewarm 消费）。这正是"内部零件"的典型位置。

📚 skills 是它的 C 位明星

整个包一半的函数都围绕 skills：SnapshotHasSkills（有没有技能）、SnapshotSkillsEqual（技能变没变）、SnapshotSkillsRaw（取出技能）。因为预热系统最关心技能。

⚡ 预热 = 把"第一次慢"变成"提前快"

agent 第一次用技能时加载会很慢，预热系统在后台提前把技能包加载好，用户真正使用时就像点了外卖已经送到了 —— 秒开。

🧵 队列解耦：拍照和用照片互不等待

创建 agent 时只把快照塞进队列就返回，后台 worker 慢慢处理 —— 前端不卡，后台不慌，各干各的。

🔒 防御性解析：坏了就当没有

所有解析函数都带 fallback：JSON 是空/null/解析失败 → 返回"没有技能"，绝不让坏数据崩掉整个流程。
