第一章 · 它是什么

为什么需要模型映射？

用户对 OMA 说："我要用 claude-sonnet-4-6"。
但 OMA 背后接的是 其他模型提供商（BYOK 场景）。

modelmapping 是 40 行的纯函数包，解决：

📖 Resolve —— 查词典翻译模型名
🚫 Validate —— 检查词典没有歧义

被 config / agents / models / platformapi / workbench 5 个包使用。

第二章 · Resolve（翻译）

查词典翻译模型名

// Resolve 返回 modelID 配置的部署模型 ID。
// 缺失、空白、恒等映射都保留原 ID。
func Resolve(modelID string, mappings map[string]string) string {
  modelID = strings.TrimSpace(modelID)
  mappedID := strings.TrimSpace(mappings[modelID])
  if mappedID == "" { return modelID }
  return mappedID
}
claude-sonnet-4-6→glm-5-turbo✅ 翻译
claude-opus-4-8→（空白）🔁 保留原名
claude-haiku-4-5→（没配置）🔁 保留原名
" claude-sonnet-4-6 "→glm-5-turbo✨ 先 Trim 再查
第三章 · Validate（防歧义）

检查词典会不会"翻译出歧义"

🚫 拒绝链式映射（会产生歧义）：
claude-sonnet-4-6 → glm-5-turbo → glm-5.2

❓ 为什么拒绝？
A 边界查 claude-sonnet-4-6 得到 glm-5-turbo，
B 边界查 glm-5-turbo 又得到 glm-5.2 —— 同一模型在不同边界解析结果不同！

✅ 允许"别名共享同一上游"（不歧义）：
claude-sonnet-4-6 → glm-5-turbo
claude-sonnet-4-5-latest → glm-5-turbo

多个 Claude 模型别名指向同一个上游模型 —— 合法！

第五章 · Insight

读完代码的深度理解

🧼 1. TrimSpace 是灵魂 —— 源和目标都 Trim，避免 "空格导致查不到" 或 "空格导致多一个映射"。

🪶 2. 缺省即透传 —— 没映射/空白映射 = 用原名：
不是"必须有映射"，而是"有映射就用，没有就原样"，降级友好。

🚫 3. 防链式 = 防"不同边界解析不同" —— 这是配置正确性的关键： 同一模型名在不同 API 入口必须解析成同一个上游模型。

💡 4. 映射表是"扁平的" —— 不允许 A→B→C 的间接层， 只允许一层直译 —— 简单、可预测、无歧义。
