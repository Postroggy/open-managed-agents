第一章 · 它是什么

Filestore 解决什么问题？

Agent 在沙箱里干活，要 读写文件 —— 但这些文件在云端的临时电脑里，
电脑一关就没了。Filestore 让这些文件 持久化、可管理、有配额。

Filestore = 沙箱文件系统服务。它提供 10 个接口：
listDirectory / makeDirectory / removeDirectory / createFile / copyFile / moveFile / moveDirectory / readFile / removeFile / readMetadata

调用方是 rclone-filestore —— 沙箱里的文件挂载工具。它把 Filestore 变成虚拟磁盘， 让 Agent 感觉自己在操作本地文件。

第三章 · 数据模型

文件树长什么样？

/（filesystem 合成根）
├── outputs/　输出目录（rclone 只读挂载）
├── skills/　技能归档（全树只读 ★）
├── uploads/　上传目录
├── transcripts/　对话记录
└── tool_results/　工具结果
      └── 普通文件（blob 存 S3）

5 个固定一级目录是 Sandbox 运行时合同 —— 不能移动、不能删除、不能覆盖。

🔑 文件对象 key 固定格式：
workspaces/{workspaceUUID}/filestores/{filesystemUUID}/blobs/{blobUUID}

不可变 blob：覆盖/复制 = 写新 key，不是覆盖旧的 → 无读写竞态 ✅

第四章 · 专用鉴权

为什么需要独立的 JWT？

Filestore 只用 专用 Filestore JWT（Bearer token）：
❌ API key、OAuth token、session-ingress JWT 都不能访问
✅ JWT 绑定 filesystem_id + 租户 + readonly

Claim约束
iss固定 open-managed-agents
aud必须含 filestore
org_uuid匹配文件系统所属组织
workspace_uuid匹配未归档工作区
filesystem_id绑定唯一 filesystem，换 ID 拒绝
readonly只读 token 才带，且只能为 true

💡 关键设计：每次请求都回查数据库（不是只验签名）——
Session 归档/终止、组织 taint 变化、CMEK 变化 → 立即撤销权限，不用等 token 过期。

第七章 · Insight

读完代码的深度理解

🧠 1. "文件系统"是假的，是真的 —— 目录树是 DB 里的 resource 行，文件内容是 S3 对象； 但 Agent 感觉是本地磁盘（rclone 挂载）。

🔒 2. 每次请求都回查 DB —— 不是"签名有效就放行"，而是"签名有效 + 此刻状态仍有效"， 实现秒级撤销。

🚫 3. 五个固定根 + /skills 全树只读 —— 运行时合同和普通用户目录严格分开， mutation 永远碰不到固定根。

🔗 4. Session 是唯一所有者 —— Code Session 只是执行实例，换沙箱不换文件柜。

⚡ 5. 不可变 blob key —— 覆盖写新 key，消灭读写竞态，历史对象天然可追溯。
