💬 Session 到底是什么？

🏛️ 不是"一条消息"
不是"一轮对话"
是「Agent 实例的一生」
第一章 · 官方定义

Anthropic 怎么定义 Session？

📖 官方文档原文（docs/managed-agents-reference/sessions.md）：

"A session is an agent instance within an environment. Each session references an agent and an environment (both created separately), and maintains conversation history across multiple interactions."

翻译：Session = 环境里的一个 Agent 实例，
它跨多次交互维护对话历史。

第三章 · 回答你的三个猜测

哪个对？

📨
发一次消息 = Session？
消息是 Event，只是 Session 里的一个条目
❌
🧵
一轮对话 = Session？
一轮对话是 Thread，Session 可以有多轮
❌
🤖
Agent 实例的一生 = Session？
从创建到归档，跨所有对话维护状态
✅
第四章 · 代码证据

创建 Session 时发生了什么？

// service.go 真实代码：一次创建 = 三个 ID 同时生成
sessionID, _ := ids.New("sesn_") // ① 会话 ID
threadID, _ := ids.New("sthr_") // ② 主线程 ID
workID, _ := ids.New("work_") // ③ 任务 ID

// ④ 同一事务写入 Session + Thread + Work
db.CreateSession(ctx, CreateSessionInput{
  Session: db.Session{
    ExternalID: sessionID,
    AgentExternalID: agent.ExternalID, // 绑定 Agent
    EnvironmentExternalID: env.ExternalID, // 绑定环境
    Status: "idle",
  },
  Thread: db.SessionThread{ ExternalID: threadID, ... },
})

💡 一次创建 = Session + 主 Thread + Work 三合一（同一事务）， 所以看起来像"一轮对话"——但实际上 Session 是容器，Thread 才是对话单元。

第五章 · 生活类比

Session = 员工的工位

🤖
员工 = Agent
被雇佣的人（配置快照）
🪑
工位 = Session
固定位置，一直保留
📂
文件夹 = Thread
每次工作的记录
📄
文件 = Event
一条条具体内容

🏢 员工今天来干活（对话1）、明天再来（对话2）——
工位（Session）还在，文件夹（历史）都在。
员工离职（Session 归档）→ 工位收走。

第六章 · 完整生命周期

Session 的一生

① 创建：POST /sessions（绑定 Agent + Environment）
② 沙箱启动：环境里的沙箱开始跑（之前的沙箱生命周期）
③ 发消息：POST /sessions/{id}/events（用户输入 → Event）
④ 实时看：GET /sessions/{id}/events/stream（SSE 流）
⑤ 跨多次交互：历史一直累积（Agent 记得之前聊的）
⑥ 归档：POST /sessions/{id}/archive（实例结束）

关键：③→⑤ 可以循环很多次，Session 始终是同一个

第七章 · Insight

读完代码的深度理解

🏛️ 1. Session 是"状态容器"不是"对话单元" —— 这是最核心的认知： 它的生命周期 = Agent 实例的生命周期。

🧵 2. Thread 才是对话单元 —— 主线程承载主要对话， 子线程承载 subagent 任务（之前 sessions 包讲过）。

📨 3. Event 是最小原子 —— 消息、工具调用、状态变化全是 Event， Session 的历史 = Event 的累积。

🔗 4. Session 绑定三样东西 —— Agent（配置）、Environment（沙箱）、 Vault（密钥），是这三者的"运行实例"。

💤 5. 跨会话恢复的地基 —— 正因为 Session 是持续的， 沙箱"pause"才有意义：用户隔天回来，Session 还在，沙箱恢复，历史都在。
