第四章 · FileBackingPath 深挖

核心函数的逻辑

// FileBackingPath：对外 mount_path → Filestore 真实路径
func FileBackingPath(mountPath string) (string, error) {
  // ① filestorepath 校验（绝对路径/长度/控制字符）
  if err := filestorepath.Validate(mountPath, false); err != nil {
    return "", err
  }
  // ② 拒绝控制字符（防路径注入）
  for _, value := range mountPath {
    if unicode.IsControl(value) { return "", errors.New("control characters") }
  }
  // ③ 前缀补全：/uploads + mount_path
  backingPath := FileSource + mountPath
  // ④ 已带 /uploads/ 前缀则直接用
  if strings.HasPrefix(mountPath, FileSource+"/") {
    backingPath = mountPath
  }
  // ⑤ 再校验一次组合后路径
  return backingPath, nil
}
⚡ 双重校验：单独路径合法 + 组合后路径也合法 —— 防止"单个合法、拼接后越界"的漏洞。
第五章 · 防路径冲突

ValidateFileMountPaths 查什么？

🚫 重复路径：两个文件挂同一个位置 → 拒绝

🔗 祖先/后代冲突：
/uploads/a 和 /uploads/a/b → 一个文件在另一个"里面" → 拒绝

为什么？ 目录和文件不能互相包含，否则挂载语义混乱。

第六章 · 和兄弟的关系

sandboxmount 依赖谁？

🔗 filestorepath —— 复用它做路径校验（之前讲过"共享路径语义层"）
📂 filestore —— 它定义的 /uploads 是 Filestore 的固定根之一
📦 files —— File resource 用它决定挂载路径

它是"路径合同"—— 让 Sandbox、Filestore、Files 三方对路径的理解一致

第七章 · Insight

读完代码的深度理解

📐 1. "合同"思维 —— 不实现挂载（那是 rclone 的事），只定义"路径长什么样"： 先有合同，再有实现。

🔒 2. 安全第一 —— 控制字符拒绝（防路径注入）+ 双重校验（防拼接越界）： 路径是攻击面，每个入口都消毒。

🧩 3. 复用 filestorepath —— 不重复造校验轮子， 统一走共享路径语义层（前面讲过这个设计）。

🚫 4. 只允许 /uploads —— source 唯一： 防止文件资源偷偷挂到 /skills 或其他固定根。

⚡ 5. 防冲突是产品需求 —— 祖先/后代冲突检查 保证挂载树永远清晰：没有文件套文件。
