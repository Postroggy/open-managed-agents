沙箱网络策略

决定沙箱里的 Agent 能访问哪些网站
第一章 · 它是什么

沙箱的网络出口怎么控制？

Agent 在沙箱里跑，可以访问外网 —— 但不能随便访问。
networkpolicy 是 出口白名单策略引擎（纯策略模块）。

internal/networkpolicy 是 纯策略模块（无 HTTP/DB）：

📐 解析 Environment 的 networking 配置（JSON）
🚦 裁决：某个目标能不能访问？（返回 Decision + Reason）
🛡️ 供 environments / codesessions / e2bruntime 使用

第二章 · 两种模式

unrestricted vs limited

🌐 unrestricted（全开）
🔓 沙箱可以访问任何网站
📭 顶层 type 不是 "cloud" 或 networking 缺失时默认
⚪ 所有目标 → Allow（Reason: unrestricted）
🔒 limited（白名单）
📋 只允许访问 allowed_hosts 列表
🔧 可选放行包管理器（allow_package_managers）
🔗 Agent snapshot 里的 MCP 服务器自动放行
🚫 其他 → Deny（Reason: host_not_allowed）

⚠️ 安全要求：调用方必须 fail closed（策略解析失败 → 拒绝，绝不降级为 unrestricted）

第四章 · 裁决原因

7 种 Decision Reason

Reason含义Allow?
unrestricted全开模式✅
explicit_host在 allowed_hosts 白名单✅
mcp_hostAgent snapshot 里的 MCP 服务器✅
package_manager_host包管理器（apt/pip/npm）✅
host_not_allowed不在白名单❌
invalid_target目标 URL 非法❌
policy_unavailable策略不可用（fail closed）❌
第五章 · 两个授权入口

HTTPS 出口 vs MCP 代理

🚦 AuthorizeHTTPS —— 沙箱出站 HTTPS（environments/e2bruntime 用）

🔗 AuthorizeMCPURL（MCPProxyPolicy）—— MCP 代理专用：
  约束 Session + 校验 AgentSnapshot 里的 MCP URL 是否合法

🛡️ MCP 授权 fail closed：snapshot 解析失败 → 拒绝（ErrMalformedAgentSnapshot）

第六章 · Insight

读完代码的深度理解

🛡️ 1. Fail closed 是灵魂 —— 所有"拿不准"的情况都拒绝： 解析失败、策略缺失、snapshot 损坏 → 一律 Deny，绝不静默放行。

🪶 2. 纯策略模块 —— 不碰 HTTP/DB，输入 JSON 输出 Decision， 任何层都能安全引用（environments/codesessions/e2bruntime 共用）。

🧩 3. 编译一次，裁决多次 —— 原始 JSON 只在解析边界存在， 授权逻辑只处理类型化 Policy（性能 + 类型安全）。

📋 4. Reason 是审计契约 —— 每次 Deny 都有机器可读原因， 日志里能回答"为什么这个请求被拒"。

🔗 5. MCP 白名单自动派生 —— Agent 配置了 MCP 服务器， 策略自动放行对应 host —— 不用手动加白名单。
