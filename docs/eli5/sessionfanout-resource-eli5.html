File 资源合同

// FileSpec = 规范化的 File 资源配置（API 默认值 + 路径校验后）
type FileSpec struct {
  fileID    string  // Files API 对象 ID
  mountPath string  // 挂载路径
}

// SessionFileBinding = 持久化无关的映射
type SessionFileBinding struct {
  ResourceID string  // Session 资源 ID
  FileID     string  // Files API 对象
  Path      string  // 存储路径
}

第五章 · Insight

读完代码的深度理解

📡 sessionfanout：解耦的广播 —— 事件生产者和消费者互不认识， 通过总线中转：新增订阅者不用改发布者。

🔴 RedisBus 是生产标配 —— 多实例必须跨进程广播， LocalBus 只是开发/测试替身（接口相同，实现可换）。

📄 sessionresource：两套解析 —— API 入口要"宽容"（补默认值）， DB 读取要"严格"（不加默认值）：同一合同，两种边界策略。

🧩 纯合同包 —— 不碰 DB/HTTP，只做"定义 + 校验"， 任何边界都能引用（和 sessioncontract 同哲学）。

🔗 多层合同叠加 —— 上限（contract）+ 路径（mount）+ 资源（resource）： 每一层都是"共享的单一事实"，防止各边界解释不一致。
