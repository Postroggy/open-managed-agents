第四章 · RunCommand 深挖

跑命令的完整生命周期

三层嵌套结构（最讲究的部分）：

// ① RunCommand 入口：校验 + 默认超时
func (p *E2BProvider) RunCommand(...) {
  if sandboxID == "" { return error }  // 必填
  if command == "" { return error }  // 必填
  if timeout <= 0 { timeout = cfg.RequestTimeout }
  return runConnectedCommand(...) // ② 连接
}

// ② runConnectedCommand：连接 + 执行（两次超时兜底）
timeout := request.Timeout
if timeout <= 0 { timeout = 60 * time.Second }  // ← 兜底 60 秒
commandCtx, cancel := context.WithTimeout(ctx, timeout)
defer cancel()
start, err := connect(commandCtx) // 连接沙箱
return executeCommand(commandCtx, ...) // ③ 执行

③ executeCommand 的并发模式（最精彩的部分）：

process, _ := start(commandCtx, request) // 启动进程
defer process.Disconnect()

// 如果有 stdin → 发送 + 关闭 EOF
if len(request.Stdin) != 0 { sendCommandStdin(...) }

// ★ 双通道竞争：goroutine 等结果，select 等超时
waited := make(chan commandWaitOutcome, 1)
go func() { waited <- process.Wait() }()  // 后台等命令结束

select {
case outcome := <-waited:        // 命令先结束 → 正常返回
  return outcome.result
case <-commandCtx.Done():     // 超时先到 → 杀进程！
  return errors.Join(ctx.Err(), killCommandProcess(process))
}
⚡ 为什么 select 双通道？防止"命令卡死永远不返回"——超时一到立即 Kill 兜底（killCtx 10 秒上限）。

第六章 · resolveNetwork 深挖

网络策略 → 沙箱白名单

func resolveNetwork(raw, work) (*SandboxNetworkOpts, bool, error) {
  if len(raw) == 0 { return nil, true, nil }  // 没配置 → 全开
  config := networkpolicy.ParseConfig(raw)
  if config.Type == Unrestricted { return nil, true, nil }  // unrestricted → 全开

  hosts := config.AllowedHostPatterns()        // 白名单
  if config.AllowPackageManagers {
    hosts += PackageManagerHosts()          // + 包管理器
  }
  if config.AllowMCPServers {
    hosts += mcpAllowedHostsFromWork(work)  // + MCP 服务器
  }
  return &SandboxNetworkOpts{AllowOut: UniqueTrimmedStrings(hosts)}, false, nil
}

🔗 联动 networkpolicy：白名单 = allowed_hosts + 包管理器 + Agent 配置的 MCP 服务器 ——
E2B 沙箱层面就执行了"只能访问白名单"，网络策略的最终落地

第七章 · 剩余方法

WriteFile / FileExists / BackgroundCommand

📝 WriteFile —— 写文件进沙箱（前置 shellQuote 安全转义）
🔍 FileExists —— sandbox.Files.Exists 检查
⏸️ StartBackgroundCommand —— 后台命令：
  · Background: true 启动
  · 校验 PID ≠ 0（防幽灵进程）
  · stdin 非空才启用 stdin 通道
  · stdin 发送失败 → Kill 兜底
🗑️ Kill —— 连接后 sandbox.Kill
⏱️ SetTimeout —— 心跳续期（timeout ≤ 0 → 用 sandboxTimeout）

第八章 · Insight

读完 501 行的深度理解

🛡️ 1. 每层都有"兜底"哲学 —— 模板三级兜底、超时两次兜底、 stdin 失败 Kill 兜底、kill 有 10 秒上限：绝不让一次失败卡死整个流程。

⏱️ 2. 超时 = 一等公民 —— Create 30s、命令 60s、kill 10s， 每个动作都有明确时限，杜绝无限等待。

🧵 3. select 双通道是 Go 并发精髓 —— 命令结果 vs 超时赛跑， 谁先到听谁的：正常返回 or 杀进程。

💤 4. "pause" 而非销毁 —— 沙箱超时暂停、可续命， 这是 Session 恢复机制的地基（前面 codesessions 讲过恢复）。

🔗 5. 网络策略最终落地在 E2B 层 —— networkpolicy 解析 → 白名单 → E2B AllowOut： 三层串联（policy → runtime → E2B 云）完成沙箱出口管控。

🔌 6. 抽象的价值 —— 8 个方法就是"沙箱契约"， 换提供商（如 AWS/自建）只需新实现，environments 零改动。
