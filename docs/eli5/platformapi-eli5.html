第一章 · 它是什么

platformapi 管什么？

用户在 控制台（Console） 上登录、管组织、看工作区……
所有控制台背后的 HTTP 接口，都在 platformapi。

internal/platformapi = 平台控制台的 HTTP 接口层：

🎛️ 20 个文件 · 19 个路由注册函数
📞 注册到 /api · /auth · /oauth · /web-api

它消费 platform 包的数据模型（上一集讲的档案层）

第二章 · 功能分组

六大功能区

第四章 · 和兄弟的关系

平台四件套

📄 platform = 档案（数据模型）→ platformapi 消费它
📞 platformapi = 接线员（本集主角，19 个路由）
🪪 platformauth = 门卫（验证登录）→ platformapi 调它
🎟️ platformsession = 售票机（会话状态）→ platformapi 存它

platformapi 是"总机"，把档案、门卫、售票机全部串起来

第五章 · Insight

读完代码的深度理解

🎛️ 1. 控制台全家桶 —— 登录/组织/工作区/计费/代理/目录， 平台控制台的全部 HTTP 面集中在这一个包。

🪶 2. 依赖 platform 数据契约 —— 自己不带模型， 全部消费 platform 包的档案 —— 分层清晰。

🔀 3. 组织级代理是 BYOK 的"控制台入口" —— 用户从控制台调模型也走 modelmapping 翻译。

📦 4. directory_servers.json 是 797KB 快照 —— 嵌入式目录快照必须保持紧凑 JSON（项目规则）。
