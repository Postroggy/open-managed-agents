🔧 scripts/：仓库的"工具架"

这个目录装的全是 bash 小工具，不参与业务逻辑，却撑起整个开发体验：
一套质量门禁（不让坏代码进仓库）· 一批开发助手（重启服务、手动测试）· 一份测试脚本

第 1 章

工具架上有 3 层架子

scripts/ 里 15 个文件，按用途分成三堆。

🛡️
质量门禁
给"提交前"和 CI 用
不是给人跑的，是给机器跑的：pre-commit 钩子 + GitHub Actions 都调它们。
作用：坏代码（超行数 / 重复 / 死代码 / 复杂度过高）在进门之前被拦下。
🚀
开发助手
给人跑的
重启后端 / 前端、用 ant CLI 手动测 API。
作用：把繁琐操作（杀端口进程、配环境变量）封装成一条命令，省得每次手动敲。
🧪
脚本自测
给门禁脚本自己做的体检
scripts/tests/ —— 门禁脚本自己的单元测试。
作用：管质量的工具，自身也要被测试。
🎯 门道 1：质量门禁脚本同时被 pre-commit 钩子（本地）和 .github/workflows（CI）调用 —— 本地没跑过，CI 也会跑；本地跑过了，CI 一定过。一套脚本两处用，保证本地体验 = 线上标准。
第 2 章

门禁文件全家福：6 个门卫 + 1 本账本

pre-commit.sh启动器：用 uv 装固定版本 pre-commit（4.6.0）再执行 —— 保证大家版本一致
pre-commit-go-lint.sh门卫 1：Go 静态检查（gofmt + golangci-lint + 不可达声明）
pre-commit-web-format.sh门卫 2：前端格式检查（项目固定版本 Prettier）
check-go-file-lines.sh门卫 3：行数上限 —— 生产 500 行 / 测试 1000 行（历史热点单独记账）
go-file-line-budgets.txt📒 账本：历史热点文件的行数预算（必须与当前行数精确一致）
check-duplicates.sh门卫 4：重复代码检测（jscpd，Go ≤3.75% / 前端 ≤1.1%）
go-dead-code.sh门卫 5：死代码检测（unused 分析器）
go-complexity.sh门卫 6：复杂度检测（cyclop 圈复杂度 ≤30 + funlen）
tests/check-go-file-lines_test.sh门卫脚本自己的单元测试

哲学：预算即契约 —— 行数、重复率、复杂度全有硬数字（500 / 1000 / 3.75% / 1.1% / 30），用 just 命令复跑（just hooks-run / just dead-code / just duplicates / just complexity）。

第 4 章

开发助手全家福：4 个趁手工具

restart-server.sh重启后端：找占用端口的进程 → kill → 等释放 → 必要时 kill -9 → 前台 go run .（可 PORT= 覆盖）
restart-web.sh重启前端：只杀本仓库启动的 Vite；端口被别的路径占用就自动选新端口（最多扫 50 个）
ant-filesFiles API 测试助手：upload / list / get / delete / download，包装 Anthropic 官方 ant CLI 指向本地服务
ant-batchesBatches API 测试助手：run / create / poll / results / cancel，支持 --stable/--beta 变体 + fixture 模式
upload-platform-files批量上传文件到本地服务（可 --dry-run / --list-after），带 "scrub" 选项清洗敏感信息

门道：ant-* 三个脚本的默认 ANT_BIN 指向 Anthropic 官方 CLI（~/GolandProjects/anthropic-sdk-all/...）， 配 ANT_BASE_URL=http://127.0.0.1:38080 打本地服务 —— 用官方客户端测自己的实现，这才是真正的兼容性测试。

第 5 章

一处值得注意的门道

门道细节为什么
一套脚本，本地 + CI 双用 check-*.sh 同时被 pre-commit 钩子和 .github/workflows 调用 本地过了 CI 必过；CI 的门禁 = 本地体验
版本固定 pre-commit 4.6.0、Prettier 项目固定版本、jscpd 从 web/node_modules 取 所有机器（含 CI）跑同一个版本，无"我本地能过"差异
budgets.txt 是账本 历史热点文件的行数预算精确记账，改文件必须同步改账本 行数只降不升，杜绝"大文件合法化"
restart-web 会认"爹" 只杀本仓库起的 Vite；别的进程占端口就换端口 不误伤他人正在跑的前端
ant 系列默认有"脏"钥匙 ant-batches 默认 API key 是明文硬编码（sk-ant-api03-...） 开发便利；生产靠真实密钥，本地无碍
上传脚本带 scrub 上传前清洗 base URL / auth token 上传到平台的文件不泄露本地配置
第 6 章

一句话全景

scripts/ 是 OMA 的开发运维工具箱：

🛡️ 质量门禁（6 个脚本 + 1 账本）—— 把"行数 / 重复率 / 复杂度 / 死代码"变成硬数字，本地与 CI 共用；

🚀 开发助手（restart-server / restart-web / ant-files / ant-batches / upload-platform-files）—— 把"重启服务、手动测 API"封装成一条命令；

🧪 脚本自测（tests/）—— 管质量的工具自身也有测试。

💡 门道总结：这些脚本不写业务，但定义了仓库的"卫生标准"—— 它们把质量规则代码化， 让每个贡献者（包括 AI）在 commit 前就收到反馈，而不是等 CI 打回。对开源项目来说，这是"社区协作纪律"的落地工具。

🎯 一句话记住本章

scripts/ = 质量门禁（6 门卫 + 账本，本地 CI 双用）+ 开发助手（重启 / 官方 CLI 测试）+ 脚本自测。
它把仓库的卫生标准写成了可执行的代码 —— 好代码不是靠自觉，是靠门禁。
