第一章 · OMA 在解决什么问题

先理解"要做什么"

🎯 OMA 的核心使命
做一个 Anthropic Managed Agents 的兼容开源实现 —— 让用户能在自己的基础设施上，跑出和官方一样体验的"托管 Agent"。
这意味着三件事：① API 合同兼容（官方 SDK 能直接连）② 沙箱运行时（Agent 真能干活）③ 管理面（组织/用户/密钥/监控）。

🧭 由此推出三个架构主轴：

主轴 A：合同驱动 —— 因为是"兼容实现"，一切以官方 API 合同为锚（错误格式、事件类型、资源上限、路由语义）。
主轴 B：租户安全 —— 因为是"托管服务"，多租户隔离是第一优先（org/workspace 两层边界）。
主轴 C：可演进 —— 因为协议在快速变化（官方不断加新能力），架构必须让"加功能"容易、"改结构"不痛。

第二章 · 六大设计决策

每个"包结构"背后都是一个决策

（不讲包名，讲"为什么这么切"）
🔌
决策 1：接口驱动（依赖倒置）
上层定义"要什么"，下层提供"实现"。调用方只依赖接口，不依赖具体实现。
💡 为什么：沙箱提供商（E2B）可以换、会话存储（Redis/内存）可以换、加密提供商（Local/KMS）可以换 —— 换实现不动业务代码。这是整个架构的"可替换性"来源。
🧩
决策 2：合同下沉（共享语义层）
把"路径/上限/事件分类/错误格式"这些多方共识抽成独立的小包，谁都用、谁也不拥有。
💡 为什么：同一份语义（如"Session 最多 500 资源"）如果每个包各写一遍，改一处漏三处 —— 用"单一事实来源"消灭漂移。也是为了避免循环依赖（db 需要路径校验但不能依赖资源包）。
🏗️
决策 3：分层 + 单向依赖
入口 → 资源 → 运行时 → 基础设施，依赖只能向下。资源层是"对外脸"，运行时层是"执行引擎"，基础设施是"地基"。
💡 为什么：可测试（每层可独立测）、可替换（换层不牵连）、可理解（新人不迷路）。db 永不 import 资源包 —— 这条铁律让架构不腐化。
⏳
决策 4：重活全异步（队列 + worker）
所有慢操作（技能装载、文件清理、事件投递）都是"入队即返回"，后台 worker 慢慢消化。
💡 为什么：用户请求必须"秒回"。技能预热 10 秒？丢队列。删文件慢？丢队列。发 webhook？丢队列。核心哲学：用户请求不等待重活。
🔐
决策 5：安全 = fail closed + 纵深防御
每一层都假设"自己可能被绕过"：鉴权层管身份，资源层管租户过滤，运行时层管网络白名单，存储层管加密，出口层管签名。
💡 为什么：托管服务的信任模型是"攻击者可能在沙箱里"。所以沙箱网络要白名单、密钥要信封加密、明文不出内存、拿不准就拒绝 —— fail closed 贯穿每一层。
🗄️
决策 6：数据按类型分仓（三驾马车）
元数据进关系库（可查询）、大内容进对象存储（便宜）、会话状态进缓存（快）。每张表 UUID 做稳定业务标识。
💡 为什么：大内容塞 DB 会拖垮查询；状态塞 DB 会慢；只有元数据需要结构化查询。UUID 让数据可搬迁、可合并 —— 架构为"可迁移"而设计。
第三章 · 决策 → 代码

这些思想在代码里长什么样

决策 1（接口驱动） → Provider 接口 / Store 接口 / KeyProvider 接口 —— 沙箱、会话、加密全是"接口 + 实现"
决策 2（合同下沉） → contract / mount / path / events 等小包 —— 只有常量/纯函数，零依赖
决策 3（分层） → 资源包 × 运行时包 × 基础包 —— 每个包职责单一、依赖单向
决策 4（异步） → Enqueue / Lease / worker 循环 —— 三处都是"入队 + 轮询 + 重试"模式
决策 5（安全） → 信封加密 / 网络白名单 / 签名头 / fail closed —— 贯穿所有层
决策 6（分仓） → "内容进 S3、元数据进 DB" —— files/memory/batches 全是一个模式

🎯 检验方法：当你看到一个新包，问三个问题 ——
① 它属于哪一层？（入口/资源/运行时/基础）② 它依赖谁、谁依赖它？（单向吗）③ 它解决哪个决策里的哪个问题？（职责清楚吗）

如果三个都能答上，说明这个包"放对了位置"；答不上，就是架构在提醒你"这里可能有问题"。

第四章 · 压缩成一段话

OMA 架构的"一句话版本"

🧠 一句话记住
OMA = 兼容官方合同的托管 Agent 平台：
· 对外 —— 用「合同下沉」保证 API 兼容（SDK 即插即用）
· 对内 —— 用「分层 + 接口」保证可演进（换实现不换业务）
· 底下 —— 用「三驾马车」存数据、「队列 + worker」扛重活
· 全程 —— 用「fail closed」守安全（纵深防御，拿不准就拒）
