第一章 · 整个包是干嘛的

为什么需要"工具目录"？

Agent 可以用 MCP 工具 —— 但工具散落在 成千上万个服务器 上。
用户怎么知道哪里有工具？mcpcatalogs 就是 工具发现服务。

mcpcatalogs 做三件事：
1️⃣ 解析：从 Agent 配置里读出 MCP 服务器（catalog.go）
2️⃣ 规范化：把 URL 归一化，语义等价的归一条（endpoint.go）
3️⃣ 探测：去访问服务器，看它提供什么工具（probe.go）

解析 Agent 的 MCP 配置

catalog.go 是整个目录的入口 —— 它把 Agent 持久化的 MCP 配置

// 最小结构：名字 + 类型 + URL

  Name string `json:"name"`

}

💡 两个设计细节：
① 空值兜底：JSON 是空或 "null" → 返回空切片（不是 nil，也不是报错）
② 统一 TrimSpace：三个字段都去首尾空白 —— 注释说得很清楚： "避免读取目录和手动刷新使用不同的 endpoint identity"

为什么重要？ 同一个 URL，一个带空格一个不带，探测时会当成两个 endpoint —— 目录就重复了。

第五章 · Insight

读完代码的深度理解

🧹 1. 身份 = 规范化后的 URL —— 目录以"规范化 endpoint"为唯一键： `HTTPS://EXAMPLE.COM:443` 和 `https://example.com` 是同一个。

🔒 2. 拒绝凭据 —— NormalizeEndpoint 拒绝 userinfo（URL 里带密码）， 避免把密钥存进目录；fragment 也拒绝。

🌍 3. 全局目录 + 匿名探测 —— 目录是全局共享的，只表示"匿名探测"， 不含任何私有服务器信息。

🪶 4. catalog.go 是纯函数 —— 不碰 DB/HTTP，只做 JSON→结构体； 同包其他文件才处理网络和存储。

💡 5. 一致性是核心 —— 注释反复强调"避免不同 identity"： 空白、大小写、默认端口都会导致重复目录，所以每一步都在归一化。
