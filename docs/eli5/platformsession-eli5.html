第一章 · 它是什么

平台会话解决什么问题？

用户在控制台登录后，怎么记住"你是谁"？
platformsession 就是存储登录状态的地方（会话存储）。

internal/platformsession = 平台登录会话存储：

🎫 3 个文件：接口 + 内存实现 + Redis 实现
🗝️ 会话 key → Session（谁登录的 + 哪个组织 + 哪个工作区）
⏰ 默认 TTL = 300 天

第二章 · 核心结构

Session 长什么样？

// 一个会话 = 用户 + 组织 + 工作区 + API Key 全家桶
type Session struct {
  ExternalID       string     // 会话 ID
  OrganizationUUID  string     // 组织
  WorkspaceUUID    string     // 工作区
  UserUUID         string     // 用户
  APIKeyUUID       string     // 对应 API Key
  ExpiresAt        *time.Time // 过期时间
}

// 关键：Session 能直接变成鉴权身份！
func (s Session) Principal() auth.Principal

💡 Principal() 是灵魂 —— 会话存的就是"一把钥匙"， 取出来直接变成 auth.Principal（鉴权身份），中间不用再查 DB。

第三章 · 接口

3 个方法

💾 Save(key, session) —— 存会话
🔍 Get(key) —— 取会话（过期自动删）
🗑️ Delete(key) —— 删会话（退出登录）

第四章 · 两种实现

内存 vs Redis

🧠 MemoryStore
⚡ 进程内 map + 互斥锁
🏠 单实例 / 开发环境用
💥 重启就丢（内存）
🔄 过期检查在 Get 时懒删除
🔴 RedisStore
🌐 Redis SET with TTL（服务端自动过期）
🏭 多实例共享（生产用）
✅ 重启不丢（持久化）
🔐 key 先 hash 再存（HashSecret）

🔑 共同的 key 设计：platform:sessions:{hash(sessionKey)} —— 不存明文 key，先哈希。

第五章 · 和兄弟的关系

平台四件套补全

📄 platform = 档案（数据模型）
📞 platformapi = 总机（HTTP 接口）
🪪 platformauth = 门卫（验证登录）
🎟️ platformsession = 售票机（本集主角：存会话状态）

platformapi 登录成功后 → Save 到 platformsession；
后续请求 → Get 出来变 Principal → 放行

第六章 · Insight

读完代码的深度理解

🎫 1. "会话 = 身份"一体化 —— Session.Principal() 把存储和鉴权打通， 存的东西直接能当钥匙用。

🔌 2. 接口隔离实现 —— Store 接口 + 内存/Redis 两个实现： server.go 组装时选一个，业务代码不关心。

⏰ 3. 300 天 TTL —— 登录状态保留近一年，用户体验好。

🔐 4. 会话 key 哈希存储 —— 即使 Redis 泄露，也拿不到明文 session key。

🏠 5. 默认内存实现 —— NewServer 默认 MemoryStore（开发友好）， 生产可换 RedisStore —— 无感知切换。
