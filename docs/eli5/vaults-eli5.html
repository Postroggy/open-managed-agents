第二章 · 两级结构

Vault → Credential

🗄️
Vault（保险库）
容器：一个组织/工作区的密钥集合，可归档
▼ 包含
🔑
Credential（凭据）
单条密钥：认证配置（公开）+ 秘密 payload（信封加密）

💡 关键设计：认证配置与秘密分离
配置（auth type/URL）明文存 DB；
秘密（token/密码）信封加密后存 SecretEnvelope —— 明文绝不留存。

第五章 · 注入决策

decideInjection 三种结果

✅ passthrough —— 无匹配凭据：头原样不动
💉 inject —— 匹配 static_bearer：设置 Bearer 头
🚫 reject —— 匹配但无法注入：返回 ErrInjectionRejected

匹配规则：host 相等 + 路径前缀匹配（hostsEqual + pathPrefixMatch）

第七章 · Insight

读完代码的深度理解

🧩 1. 配置与秘密分离 —— 认证配置明文、秘密信封加密： 列表接口不碰秘密，只有注入时才解密。

💉 2. 注入是"按需解密" —— 明文 token 生命周期 = 一个请求： 不解密不缓存，用完即弃（暴露面最小）。

🎯 3. URL 匹配注入 —— host + 路径前缀决定用哪条凭据： 多个 MCP 服务器共享一个 vault，自动路由。

🔗 4. 和之前讲的完全串起 —— secrets（信封加密）→ vaults（保险库） → injector（注入）→ mcp_proxy（之前 codesessions 讲的凭证注入边界）。

🚫 5. fail closed —— 匹配但无法注入 → reject： 绝不把"没带 key 的请求"放出去（拿不准就拒绝）。
