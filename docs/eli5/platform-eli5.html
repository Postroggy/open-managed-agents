第一章 · 它是什么

这个包没有 handler？

它没有路由、没有 HTTP 入口 —— 只有 数据模型 和 工具函数。
给 platformapi（真正的接口层）和 db 层用。

internal/platform = 平台控制台（Console）的数据档案层：

📄 定义控制台的数据结构（用户/组织/工作区/请求/工作台）
🔍 workspace 作用域解析（用户当前在哪个工作区）

被 platformapi / workbench / db / api 使用

errors.go

第四章 · 和兄弟的关系

platform vs platformapi vs platformauth

🛰️ platform = 档案（数据结构 + 工具）
📞 platformapi = 接线员（真正的 HTTP 接口层，调用 platform 的数据）
🪪 platformauth = 门卫（平台身份验证）
🎟️ platformsession = 售票机（登录状态会话）

platform 是最底层的"数据契约"，其他平台包都依赖它。

第五章 · Insight

读完代码的深度理解

📄 1. 数据契约分层 —— platform 定义"控制台数据长什么样"， platformapi 负责"怎么接进来"：模型和接口解耦。

🪶 2. 无业务逻辑 —— 除了 workspace_scope 的默认选择， 其余全是纯数据结构 —— 简单、可测试。

🔗 3. 跨层共享 —— db 层也能引用 platform（bootstrap 时）， 说明它是"领域模型"而非"接口模型"。

🧩 4. workspace_scope 是唯一"会动脑"的文件 —— 默认工作区排序规则（创建时间优先）是产品逻辑的集中点。
