🛡️ hop-by-hop header 只对上游连接有效，不能泄漏给客户端

第四章 · SSE 流式秘诀

为什么响应能实时到达？

// 每个 32 KiB 块写完立即 flush
func (w flushingResponseWriter) Write(data []byte) (int, error) {
  w.writer.Write(data)
  w.controller.Flush() // ← 关键：每块都刷
}

// SSE 响应加 no-cache + 关缓冲
Cache-Control: no-cache
X-Accel-Buffering: no

🌊 三个秘诀：
① 32 KiB 小缓冲（不是整响应读入内存）
② 每块 flush（flushingResponseWriter）
③ X-Accel-Buffering: no（关掉反向代理缓冲，事件立刻到达 Claude Code）

第五章 · Insight

读完代码的深度理解

🪶 1. 极简代理哲学 —— 不解析、不存储、不改内容：
它唯一加的东西是「上游密钥」和「删除的 header」—— 一切都是为了"安全地透传"。

🌐 2. 凭证边界 —— 客户端永远看不到上游 key；
用户用自己 OMA 的 key，OMA 用上游的 key —— 两套凭证隔离。

📦 3. 内存恒定 —— MaxBytesReader（不预分配）+ 32 KiB 缓冲： 不管 1MB 还是 32MB 的响应，内存占用都一样小。

🔌 4. 连接池复用 —— MaxIdleConnsPerHost=32：高并发转发不建新连接。

⏱️ 5. 不设超时 —— SSE 生命周期由请求 context 控制： 客户端断开 = 上游断开，无悬挂连接。
