第一章 · 它是什么

storage 管什么？

系统里的 大文件（文件内容、记忆、技能包、批处理结果）
都存对象存储 —— storage 是它们的统一仓库管理员。

internal/storage = 对象存储抽象层（AWS SDK for Go v2）：

🗃️ Client —— 共享连接池 + 凭证
📦 ObjectStore —— 绑定单个 bucket 的操作边界

被 files / memory / skills / batches / filestore 全部共享

第二章 · 两级结构

Client → ObjectStore

🔌
Client（全局唯一）
启动时创建一次：复用 AWS SDK 连接 + 凭证
storage.New(cfg)
▼ ForBucket(name) 按名称派生
📦
ObjectStore（绑定单 bucket）
Upload / Open / Copy / Delete / Ensure / Name
不新建网络连接，只生成 bucket 作用域对象
▼
☁️
S3 / MinIO
真实对象存储（生产 S3，开发 MinIO）

💡 设计：一个 Client 派生出多个 ObjectStore（不同 bucket）—— 连接不重复，bucket 隔离清晰。

第三章 · 5 个操作

ObjectStore 接口

⬆️
Upload
上传（已知/未知大小流，分片 16MiB）
⬇️
Open
打开（支持字节区间 Range 读取）
📋
Copy
复制（服务端复制）
🗑️
Delete
删除（普通/精确版本/全部版本）
🛡️
Ensure
确保 bucket 存在（无则创建）
🏷️
Name
返回 bucket 名

💡 版本控制支持：Delete 分三种（普通删除/精确版本/同键全版本清理）， 配合 S3 版本化 —— 这就是之前讲 filestore"不可变 blob"的底层能力。

第四章 · 错误分类

统一错误映射（errors.go）

Kind含义识别方式
ErrNotFound对象不存在NoSuchKey / NoSuchBucket / 404
ErrAccessDenied凭证无效/无权限AccessDenied / 401 / 403
ErrConflict冲突（bucket 已存在等）BucketAlreadyExists / 409 / 412
ErrInvalidRange范围读取越界InvalidRange / 416

🧩 StoreError 包装：保留 Operation + Bucket + Key + Code + Cause，
通过 errors.Is 暴露稳定分类 —— 上层不用猜 S3 错误码。

第五章 · 谁在用

共享同一个仓库

📁 files —— 文件内容
🧠 memory —— 记忆内容（之前讲过：内容存 S3）
🧰 skills —— 技能包归档
📦 batches —— 批处理结果 JSONL
📂 filestore —— 沙箱文件 blob
🧹 cleanup —— 清理队列消费（按任务 bucket 选择 store）

全部通过 storage.Client.ForBucket 派生自己的 ObjectStore

第六章 · Insight

读完代码的深度理解

🔌 1. "一个连接，多个 bucket" —— Client 复用连接， ForBucket 只生成作用域对象：资源利用最优。

🎯 2. 接口 = 需求清单 —— Upload/Open/Copy/Delete 恰好是 所有资源包需要的 4 个操作：不多不少。

🧩 3. 错误统一分类 —— StoreError 把 S3 各种错误码 归为 4 类，上层 errors.Is 判断，不碰 AWS SDK 细节。

📦 4. 流式优先 —— Upload 支持未知大小流、Open 支持 Range： 大文件不整读进内存（32MiB 限制配合）。

🗑️ 5. 版本删除是"硬能力" —— 精确版本删除/全版本清理 是 filestore 不可变 blob 的底层保障。
