第一章 · 它是什么

sessions 包管什么？

用户和 Agent 的 每一次对话 都是 Session。
sessions 包是对话的 一站式服务（21 个文件，核心资源包）。

internal/sessions 覆盖：

💬 会话 CRUD —— 创建/查看/列表/更新/归档/删除
📡 事件流 —— 实时 SSE（stream_hub）
🧵 线程 —— 子任务线程管理
📁 资源 —— 文件资源挂载
📢 广播 —— 事件总线（之前讲的 sessionfanout）
🔔 webhook —— 事件通知（webhook_bridge）

第五章 · 和兄弟的关系

sessions 是"对外脸面"

💬 sessions = 对外 API（用户看到的对话）
🎬 codesessions = 背后发动机（沙箱 worker 通信）
📢 sessionfanout = 广播总线（事件分发）
📄 sessioncontract = 合同常量（上限）
📂 sessionresource = 资源合同（文件）
🏷️ managedagentsevents = 事件字典（分类裁决）

sessions 把这些全部串起来，对外提供完整的对话 API

第六章 · Insight

读完代码的深度理解

🏛️ 1. 最核心的资源包 —— 21 个文件、路由最多： 对话是产品的灵魂，sessions 是灵魂的载体。

🔁 2. 事件闭环设计 —— 用户输入 → 广播 → SSE → worker → 回流： 整条链路解耦（fanout 总线 + stream_hub 中枢）。

🎧 3. stream_hub 是 SSE 心脏 —— 管理所有实时连接： 订阅/退订/广播/重置（Session 归档时重置连接）。

🧵 4. 线程 = 子任务 —— 一个 Session 可有多个线程 （subagent 任务），各自有事件流。

🔗 5. 大量复用共享包 —— managedagentsevents（分类）、 sessionfanout（广播）、sessionresource（资源）—— sessions 是"组装者"而非"发明者"。
