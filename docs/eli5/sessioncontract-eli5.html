📜 internal/sessioncontract
会话资源合同

🤝 15 行的小包
规定"一个会话最多能挂多少资源"
第一章 · 它是什么

为什么需要"合同"？

Session 可以挂资源（文件、工具结果…）。
但 最多挂多少？ —— 这个上限必须全局统一。

internal/sessioncontract = 会话资源合同（15 行）：

📜 只定义 3 个常量（没有函数！）
🔗 被 db / sessionresource / deployments 三个包共享

一句话：全系统对"资源上限"的唯一事实来源

第二章 · 3 个常量

合同内容

🏷️
FileResourceType
"file"
资源类型：文件
📊
MaxResources
500
Session/Deployment 资源数组上限（官方天花板）
📁
MaxFileResources
500
文件条目上限（= MaxResources）

💡 两个 500 但语义不同：MaxResources 是"总预算"（混合类型）， MaxFileResources 是"文件能占满整个预算"。
官方文档允许文件填满全部资源预算 → 所以两者相等。 保留两个名字是为了让调用点说清楚自己指的是哪个限制。

第三章 · 为什么单独成包

合同要"共享"而不能"重复"

🔗 三个包都需要这个上限：

🗄️ db/sessions.go —— 写 Session 时校验资源数
📂 sessionresource/file.go —— 加文件时校验数量
🚢 deployments/resources.go —— 部署时校验资源数

如果每个包各自写死 500 —— 有一天改成 600 要改 3 处，漏一处就出 bug。
放一个包共享 —— 改 1 处全生效。

第四章 · 完整代码

15 行就这些

// Package sessioncontract 包含稳定的 Session 资源 token 和限制，
// 由 API 合同边界和持久化边界共享。
package sessioncontract

const (
  // 资源类型：文件
  FileResourceType = "file"

  // 官方 Claude managed-agents 对顶层 Session/Deployment
  // resources 数组（混合类型）的上限
  MaxResources = 500

  // 该数组中文件条目的上限。
  // 官方文档允许文件占满全部预算，故等于 MaxResources。
  // 保留两个名字以便调用点说明各自含义。
  MaxFileResources = MaxResources
)
第五章 · Insight

读完代码的深度理解

🎯 1. "合同"命名有深意 —— 不是 "limits" 而是 "contract"： 暗示这是官方 API 合同的一部分（Claude managed-agents 兼容）。

🧩 2. 共享常量 = 防漂移 —— 三处校验读同一常量， 永不出现"db 说 500、sessionresource 说 600"的不一致。

🪶 3. 零依赖包 —— 没有 import，任何包都能引用： 这是 Go 里"常量下沉"的标准做法。

📝 4. 注释即合同文档 —— 注释解释了"为什么两个 500"、 "为什么官方允许文件占满"，后人不会误改。

🔗 5. 与官方对齐 —— 500 来自 Claude 官方文档： OMA 的 API 合同与官方 managed-agents 一致（前面 gap 分析的核心目标）。
