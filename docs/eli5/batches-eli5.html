📦 internal/batches
批量消息处理

🎪 像「快递驿站」一样
把很多小包裹攒起来，一次性发出去
第一章 · 它是什么

为什么需要「批量」？

你有一个 API，一次只能处理一条消息。
但有时你有 100 条 消息要发 —— 一条条发太慢了！

batches 包帮你把这 100 条消息打包成一个 批次（Batch）， 后台 worker 慢慢一条条处理，最后给你一个结果文件。

对应 Anthropic API 的 /v1/messages/batches 端点 —— 完全兼容。

第二章 · 批次的一生

一个批次的完整旅程

像寄快递一样：下单 → 中转 → 送达 → 签收

📝
创建批次：POST /v1/messages/batches，把 100 条消息打包
处理中 in_progress
▼
🏭
后台 worker 处理：每 5 秒扫一次队列，一条条发到上游 Anthropic
可能失败重试（最多 10 次）
▼
📊
统计结果：成功多少、失败多少、还在处理多少
succeeded / failed
▼
📦
生成结果文件：把所有结果写成 JSONL 文件，存到对象存储
结果可下载
▼
🗑️
到期清理：结果保留 N 天，过期自动删除（expiry sweep）
干净收尾
第三章 · 状态机

批次的状态流转

每个批次都有个「状态」，像快递单号一样追踪

🕐

→
✅

❌

→
⏹️
cancelled
用户取消
→
⌛

结果过期
第四章 · 对外接口

你可以对它做什么？

➕
创建：POST / → 提交一个新批次
📋
查看列表：GET / → 所有批次
🔍
查看详情：GET /{id} → 单个批次状态
✋
取消：POST /{id}/cancel → 取消还没处理的
🗑️
删除：DELETE /{id} → 删除批次
📥
下载结果：GET /{id}/results → 结果 JSONL 文件
