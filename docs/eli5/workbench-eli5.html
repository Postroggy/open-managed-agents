第一章 · 它是什么

workbench 管什么？

平台控制台有个 "工作台" 功能 —— 调 Agent 提示词、生成测试用例、评估效果。
workbench 是它的后端。

internal/workbench = 提示词工作台后端（4 个文件）：

📝 Prompt 管理 —— 创建/编辑/版本/分享/KV 存储
🧪 评估 —— evaluations + 测试用例生成
✨ AI 生成 —— generate_prompt / generate_title / 流式输出
📊 模型与限额 —— models / rate_limits

第四章 · AI 生成流程

generate_prompt 怎么工作？

✨ handleWorkbenchGeneratePrompt：
  · 接收用户请求（提示词描述/变量）
  · 转发到上游模型（AnthropicUpstream）
  · 流式返回（SSE 实时生成效果）

🧪 handleWorkbenchGenerateTestCase：
  · 生成测试用例变量值
  · 本地存储（sync.Map 缓存）
  · 流式写出生成结果

📊 models / rate_limits_v2：
  · 工作台可用的模型列表 + 限额查询

第五章 · Insight

读完代码的深度理解

🧪 1. 是"调提示词的实验室" —— prompt 版本管理 + 评估 + 测试用例： 产品团队迭代 Agent 提示词的完整工作流。

✨ 2. AI 辅助是重头 —— generate_prompt/title/completions： 工作台本身用模型来帮用户写提示词（自举）。

🔗 3. 和平台层集成 —— RegisterOrgWorkbenchRoutes 挂到 组织路由下（之前 platformapi 讲过），用 X-Workspace-ID 头。

📦 4. 测试用例本地缓存 —— sync.Map 存生成的用例， 不持久化（轻量辅助，不是核心数据）。

🗄️ 5. DB 表 —— workbench_prompts / revisions / kv / evaluations （之前 db 包讲过这些表）。
