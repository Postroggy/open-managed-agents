internal/admin 是干嘛的？

打个比方：它就像一家公司的「行政部」

1 它在公司的哪个位置？
🏢 整个后端服务 = 这家公司 internal/api/server.go
员工入口
/v1/*
普通开发者的日常工作入口
（调 Claude 兼容 API 干活）
行政部
/organizations/*
管「公司怎么运转」的地方
（招人、分部门、发钥匙、看账）
🔑 注意：这个行政部只管自己这一家公司（组织），不是管理所有公司的大总部。
2 行政部都干哪些活儿？
👥

管人

邀请新同事入职，调整职位，让不合适的人离开。

GET /users · POST /invites
🏢

分部门

建新部门（workspace）、解散旧部门、安排谁的座位权限。

POST /workspaces · .../members
🔑

发门禁卡

查看公司有哪些 API key，改名、停用，谁还能进门一目了然。

GET /api_keys · POST /{id}
🌍

管供应商

对接外部模型/算力供应商的密钥，检查人家的货还好不好用。

POST /external_keys · .../validate
📊

算账

这个月消息用了多少、Claude Code 用了多少、花了多少钱。

GET /usage_report · /cost_report
🚇

管门禁隧道

进出外部的安全通道，定期换密码（token）、发通行证。

POST /tunnels/{id}/rotate_token
3 行政部内部怎么配合？
handler.go 前台接待：有人来办事，先接单、登记，再把活儿转给后面的人 接单
▲ 转单 ▼ 回复 ⇅
service.go 办事主管：真正干活的人 —— 查权限、走流程、读写资料库 办事
▲ 查/写 ▼ 结果 ⇅
dto.go + domain_*.go 档案柜：各种表格（DTO）和名词定义（组织/部门/钥匙长什么样） 档案
4 为什么叫 internal（内部）？

因为它和员工干活用的入口 分开走：员工从大门口进（/v1/*），行政部在独立的后院办公（/organizations/*），两边的门禁是两套，互不相通。

员工卡 · /v1/*
普通开发者用自己的 key 调 Claude 兼容 API，只能碰自己的资源。
行政钥匙 · /organizations/*
管理员用组织鉴权，管人、管部门、管 key、看账，和对外 API 隔离。
一句话：internal/admin = 这家公司的行政部
管人 · 分部门 · 发门禁卡 · 对接供应商 · 算账 · 管安全通道
